# Демонстрация этапа 3

> Исторический сценарий приёмки Activity, статистики и представлений.
> Актуальный операторский путь — [operator.md](operator.md); сквозной
> сценарий — [demo-stage-4.md](demo-stage-4.md).

Fixture e2e или development-стек. Не применять к production.

1. `make e2e` или войти оператором в UI. Открыть установку
   `91000001` / `f1a00000-0000-4000-8000-000000000001`. Карточка
   показывает sync `idle` и лаг `12`, не «нет активности».
2. «Настройки Activity и lead-status». Изменить retention_days, подтвердить,
   дождаться операции (202 ≠ завершение), обновить страницу — значение
   сохранено. Повтор с чужим `expected_updated_at` даёт conflict и
   текущие числа без тихой перезаписи.
3. «Синхронизировать сейчас»: сначала pending, затем succeeded.
4. Обзор: период 24h/7d/30d в URL. Отключения = `0`, задержка p50 = `—`.
   Клик по показателю открывает `/stats/accounts`.
5. На списке аккаунтов сохранить представление, выбрать его из списка.
6. Viewer: кнопки записи скрыты; прямой POST — 403.

Автопроверки: `make test`, `make integration-test`, `make e2e`.
Core admin GET этапа 3 может ещё приземляться на
`amocrm-pro` `feature/admin-activity`; Admin API зеркалит контракт,
демо без Core идёт через fixture.
