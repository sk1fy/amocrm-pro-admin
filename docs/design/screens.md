# Карта экранов и переходов

Разделы верхнего уровня фиксированы заданием: Обзор, Аккаунты, Виджеты,
Операции, Система. Карточка аккаунта имеет вкладки Обзор, Виджеты, Операции,
История. Настройки конкретного продукта открываются внутри его подключения.

Старая админка (`rakurs-ssd`) изучена как источник сценариев: карточка клиента
с поддоменом/ID/тарифом/датами, менеджер виджетов с действиями «Проверить»,
«Приватная интеграция», «Продлить», «История продлений», страница Activity с
полями «последний синк», «мин/макс дата в БД», «курсор», «статус синка», «текст
ошибки» и действием «Синхронизировать» (ручной диапазон до 14 дней, статусы
`success`/`failed`/`token_revoked`). Состояния подключения старой системы —
`activated`, `access_only`, `access_lost`, `not_installed`, `disabled`; они
смешивали OAuth-факт с заполнением формы установки, а проверка подключения
возвращала булев результат без классификации ошибок. Новый словарь
([states.md](states.md)) разделяет эти факты и классифицирует проверку
OAuth. Тарифы, бонусы, партнёры и вход в ЛК клиента в текущий объём не
входят.

## Маршруты

| Путь | Экран | С этапа |
| --- | --- | --- |
| `/login` | Вход | 1 |
| `/` | Обзор | 1 (минимум), 3 (статистика) |
| `/stats/accounts?metric=&period=` | Аккаунты показателя статистики | 3 |
| `/accounts?q=&product=&connection=&problem=&sort=&cursor=` | Список аккаунтов | 1 |
| `/accounts/:accountId` | Карточка аккаунта → вкладка Обзор | 1 |
| `/accounts/:accountId/widgets` | Вкладка Виджеты (подключения) | 1 |
| `/accounts/:accountId/widgets/:backend/:connectionId` | Карточка подключения | 1 |
| `/accounts/:accountId/widgets/:backend/:connectionId/settings` | Настройки модуля (Activity/lead-status) по продуктам и возможностям бекенда; без `settings` ссылка скрыта, неподдерживаемый модуль — «настройки недоступны» | 3–4 |
| `/accounts/:accountId/operations` | Вкладка Операции (jobs, команды, операции) | 1 |
| `/accounts/:accountId/history` | Вкладка История (аудит Core + аудит админки по объекту) | 1 |
| `/widgets` | Каталог продуктов и интеграций | 1 |
| `/widgets/:backend/:integrationId` | Карточка интеграции: параметры, сервисы, подключения, статистика | 1 |
| `/operations?status=&type=&backend=&cursor=` | Задачи и попытки по всем аккаунтам | 1 |
| `/operations/admin?state=` | Операции админки (команды сотрудников) | 2 |
| `/system` | Реестр бекендов: статус, тип, контракт, ревизия, возможности, последний ответ, ошибка | 1–4 |
| `/system/employees` | Сотрудники и роли | 1 (admin) |
| `/system/sessions` | Мои сессии | 1 |
| `/system/audit?employee=&action=&cursor=` | Аудит действий сотрудников | 1 |

Все фильтры, сортировка и курсор пагинации живут в URL (search params).
Прямая ссылка на любой экран после входа открывает именно его; до входа —
редирект на `/login?next=`.

## Ключевые переходы

```text
Вход
  └─> Обзор ──(проблемные подключения)──> Аккаунты с фильтром problem=…
        └─> Аккаунты ──(поиск по ID / домену / ссылке)──> Карточка аккаунта
              ├─ Обзор: сводка подключений, агрегированное состояние, разбивка
              ├─ Виджеты: список подключений ──> Карточка подключения
              │     ├─ Авторизация, webhook, гранты, Activity pilot/доставка
              │     ├─ Последние jobs и ошибки
              │     └─ действия: проверить, reconcile, enable/disable, revoke, uninstall
              ├─ Операции: jobs аккаунта, попытки, операции админки
              └─ История: аудит Core по установкам + аудит админки по аккаунту
Виджеты ──> Карточка интеграции ──> список её подключений ──> Карточка аккаунта
Операции ──> Job ──> Карточка подключения / аккаунта
Система ──> Бекенд ──> ссылки в мониторинг с контекстом
```

## Экраны

### Вход

Вход по email сотрудника и паролю. На широком экране слева расположена
светлая графическая композиция с перспективными рамками и подписью
«Всё в своём ракурсе.», справа — белая область формы. Кнопка использует
проектный `--color-accent`, при наведении — `--color-link-hover`.
На мобильном экране композиция сворачивается в короткую шапку; начало
формы не смещается при ошибке. Регистрации и внешних способов входа нет.

Общий `BrandLogo` используется на входе и в боковом меню приложения,
включая мобильное меню. Логотип соответствует SVG, предоставленному
пользователем и используемому на [сайте Ракурс](https://ka.rkrs.ru/):
три столбца с исходной геометрией, первые два белые с прозрачностью
0.35/0.65, третий `#5cc4bf`. Тёмная подложка сохраняет читаемость белых
столбцов на светлом интерфейсе. Бирюзовый цвет используется только в
логотипе. Тема и шрифты остальных экранов не изменены; системный
sans-serif применяется только на входе.

Переключатель видимости пароля работает с клавиатуры и не меняет значение.
Во время запроса кнопка «Войти» недоступна, текст «Выполняется вход…»
объявляется через `role=status`. Ошибки объявляются через `role=alert`.
После входа — переход на безопасный `next` или Обзор. Ошибки учётных
данных, ограничения частоты и недоступности сервиса различаются по
[словарю состояний](states.md#ошибки-входа).

### Обзор

Оперативный дашборд по правилам
[ADR-0021](../adr/0021-calm-interface.md). Шапка: заголовок, переключатель
периода `24 ч / 7 дн / 30 дн` (`period` в URL) и компактное обновление.

- Полоса состояния (`GET /stats?period=`, `GET /system/backends`):
  недоступные бекенды, ошибки задач, повторная авторизация, проблемы
  синхронизации (7 суток). Ноль приглушён, число больше нуля — тоном
  `action` со ссылкой «Открыть» (`/operations?status=failed` или
  `/stats/accounts?metric=&period=`); отсутствие — «—».
- «Требуют внимания»: счётчики `GET /accounts?problem=`, одна строка на
  проблему — точка тона, название, рекомендуемое действие, число
  аккаунтов, «Открыть →» на `/accounts?problem=&origin=all`. Ненулевые
  и недоступные сверху по тону; нули свёрнуты в «Пройдено проверок».
  Без открытых проблем — одна строка «открытых проблем нет».
- «Использование за период»: новые подключения, отключения, активные
  аккаунты со ссылками на `/stats/accounts`, последнее использование.
  Непроверенные и временные ошибки проверок, задержка p50 — в
  «Технических показателях».
- «Бекенды»: строка на бекенд — имя, состояние (норма текстом),
  время проверки; причина отсутствия данных или ошибка. `unknown` —
  «ещё не опрашивался»; `unavailable` — источник недоступен. Ревизия и
  контракт — на странице «Система».
- «Фоновые задачи»: суммы очередей по статусам, 10 последних
  `failed`/`dead` jobs (код типа в подсказке); пустой список — строка
  «нет задач с ошибками», отказ источника — отдельное состояние.
  Очереди по типам — в раскрытии «Очереди по типам».

### Аккаунты

- Шапка: заголовок, короткое описание, обновление; источники и время
  наблюдения — в подсказке обновления.
- Поле поиска принимает: числовой `account_id`; поддомен `example`; домен
  `example.amocrm.ru` / `example.kommo.com`; полную ссылку
  `https://example.amocrm.ru/leads/detail/123` (извлекается домен). Нормализация
  — на сервере, клиент отправляет строку как есть.
- Фильтры в строке: поиск, проблема, продукт. Под «Ещё фильтры»:
  проверка amoCRM, состояние установки, происхождение (раскрыто, если
  один из них активен). Активные фильтры — чипы со снятием и «Сбросить
  фильтры». Сохранённые виды — выбор и «Сохранить вид» в той же строке;
  общее помечено «доступно всем администраторам»; обновление и
  переименование через `PATCH /views/{id}` (`views:write` у operator+).
- Колонки: аккаунт (домен — главная ссылка, под ним ID и метка
  «тестовые данные» для `fixture`), виджеты (чип на подключение с
  точкой: состояние установки, а при норме — проверка amoCRM; обе
  подписи в подсказке), состояние аккаунта (норма текстом, отклонение
  бейджем), активность (относительное время). Агрегат аккаунта не
  заменяет состояния подключений.
- Пагинация курсором; размер страницы 25/50/100 — в строке пагинации,
  навигация скрыта, если страница одна. Неизвестное общее число не
  показывается: «Показано N» без «из —».
- Баннер «Часть источников недоступна» из `sources`.
- Пустой результат отличает «ничего не найдено», «нет аккаунтов» и
  «источник недоступен».

### Карточка аккаунта — Обзор

Шапка (общая для вкладок): домен, ID, число подключений, состояние
аккаунта только при отклонении, метка `fixture`, обновление. Причины —
строкой «Требует внимания: …» с бейджами проблем. Ссылки «назад» нет —
её заменяют крошки. На карточке подключения шапка аккаунта не
показывается: у подключения своя шапка с аккаунтом в подписи.

Тело: «Подключённые виджеты» — карточка на подключение: интеграция,
состояние установки, продукты, авторизация с проверкой amoCRM, webhook
и текст ошибки webhook (подпись над значением); `observed_at`
в подсказке, устаревшие данные отмечены. Отдельной строки проблем нет:
каждая проблема уже видна тоном своего поля, а причины аккаунта —
в шапке. Клик — карточка подключения.
Блок «Подписка» (`GET /accounts/{id}/subscription`): план, состояние
(`active`/`trial`/`expired`/`cancelled` и `unknown` с `raw`), срок,
возможности. Пустой ответ — «данные подписки недоступны», а не «нет
подписки»; отказ источника не скрывает другие блоки.

Вкладка «Виджеты» сравнивает подключения таблицей: виджет с продуктами,
установка, авторизация с проверкой amoCRM, webhook, контроль
активности. Норма — текстом с точкой, отклонение — бейджем; столбца
«Проблемы» нет — он повторял те же состояния.

### Карточка аккаунта — Пользователи

URL: `/accounts/{id}/users`, вкладка «Пользователи» после «Виджеты»
(`GET /accounts/{id}/crm-users`). Состояние чтения, «Всего: N», срок
снимка Core и ссылка на подключение, через которое читали. Таблица: ID,
Имя, Статус (Активен/Неактивен), Администратор (Да/Нет), сортировка по
столбцам. Список читается при открытии вкладки и по «Обновить», без
polling. В состояниях кроме `ok` — «Список пользователей неизвестен» с
пояснением из [states.md](states.md). Email, телефоны, группы и права не
показываются.

### Карточка подключения

URL: `?section=status|auth|webhook|activity|jobs|history|tech`.
Без параметра открывается первый проблемный раздел. Сверху всегда сводка
здоровья и центр проблем
([ADR-0015](../adr/0015-connection-diagnostics-ux.md)).

Шапка — своя, шапка аккаунта на этом экране не показывается
([ADR-0021](../adr/0021-calm-interface.md)): «Подключение <код
интеграции>», в подписи домен аккаунта (ссылка), ID, итог
`connection_health` (норма текстом) и метка `fixture`; справа
компактный переключатель подключений аккаунта (список и ←/→) и
обновление. Под шапкой — «Требует внимания» с 1–3 причинами и
ссылками на разделы (или «Активных проблем нет»), затем пункты сводки
текстом с точкой: авторизация, webhook, Activity, синхронизация,
последняя проверка.

Команды — одна строка:

- основная — «Проверить подключение»;
- состояние — включить **или** отключить;
- webhook — восстановить, если подписка не активна;
- Activity — ссылка на настройки и одна команда пилота по текущему
  состоянию;
- «Ещё» / опасная зона — сброс авторизации, удаление, история команд.

Результат команды показывается под строкой команд с её названием и не
растягивает кнопки. Разделы не дублируют команды строки.

Секции вкладок:

1. **Обзор** (`status`): интеграция, домен, состояние установки, дата
   установки; здоровые блоки идентификации и грантов свёрнуты,
   проблемные открыты. UUID — во вкладке «Технические данные».
2. **Авторизация**: наличие credentials отдельно от проверки amoCRM;
   срок как относительное время; версии ключа — технические детали.
3. **Webhook**: число событий с раскрытием по сущностям, подтверждённые
   адреса доставки (не «destinations»), ошибка только если есть;
   последняя успешная проверка — `checked_at` без `last_error`.
4. **Activity**: пилот отдельно от доставок; доставки таблицей (последние
   5, «Показать все»); sync с конкретной причиной простоя и timeline;
   длительность синка — только если её можно вывести из
   `last_event_at`/`last_success_at`.
5. **Задачи**: фоновые jobs, группировка по типу, ошибки сверху.
6. **История**: действия пользователей/системы, не дубль очереди jobs.
7. **Технические данные**: UUID, версии, источник, ссылки
   наблюдаемости.

Внутри разделов норма — текстом, коды задач, событий и аудита — в
подсказке, идентификаторы и полное время — в технических данных
карточки строки; строка таблицы открывает карточку.

Связанные ошибки Core admin auth — один инцидент. Каждая секция —
независимое наблюдение: отказ одной не скрывает другие.

### Карточка аккаунта — Операции и История

Операции: таблица jobs аккаунта из
`/api/v1/accounts/{account_id}/jobs`. Фильтры одной строкой: быстрые
«Все / Ошибки / В очереди», тип задачи, «Найти» и обновление; полный
список статусов — под «Ещё фильтры» (раскрыт, если выбран статус вне
быстрых); размер страницы — в пагинации. Фильтры и курсор в URL. Столбцы: задача
(русское название, код в подсказке; тип без названия — код), статус
(норма текстом), виджет (название интеграции из карточки аккаунта),
обновлено; «Попытки» и «Ошибка» — только если в выборке есть
неуспешные задачи. Строка открывает карточку задачи: безопасные поля,
попытки, повтор при `retry_allowed`; код, ID и актор — в «Технических
данных». Внизу — ссылки на команды сотрудников по каждому виджету.

История: лента Core audit по установкам аккаунта + admin audit по
объектам аккаунта, сгруппированная по дням («Сегодня, 6 ноября»).
Строка: время, русское название события (код и источник в подсказке),
кто выполнил, объект — название виджета вместо UUID со ссылкой на
подключение. События операций называют команду из `metadata.command`
(«Операция выполнена: «Проверить подключение»»). Одинаковые события
подряд по тому же объекту и команде сворачиваются в одну строку «×N». Неуспешные (`failed`, `denied`,
неизвестный исход) отмечены бейджем и полосой слева.

### Виджеты

Шапка: выбор бекенда, «Создать интеграцию» (форма в диалоге команды),
обновление. Столбцы: интеграция (код — ссылка; бейдж состояния только
если не `active`), продукты (чипы; бейдж только для невыданных),
подключения (общее число и бейджи только для проблемных состояний),
события webhook числом с раскрытием по сущностям. Хост редиректа — в
карточке интеграции.

Карточка интеграции: шапка с кодом, состоянием при отклонении и числом
подключений; действия — «Изменить параметры», только применимое из
«Включить/Отключить интеграцию», остальное («Заменить секрет»,
«Настроить сервис», «История команд интеграции») — в «Ещё»; результат
команды под шапкой. Тело: продукты, таблица подключений (домен аккаунта
— ссылка на подключение, состояние текстом), «Технические данные»:
бекенд, ID интеграции Core, `client_id` (публичный UUID интеграции
amoCRM), `redirect_uri`, `key_version`, `updated_at`, события webhook.
Секретов нет: `client_secret` — только `key_version` и `updated_at`.

### Операции (глобальные)

Jobs всех аккаунтов: те же строка фильтров и таблица, что во вкладке
аккаунта; бекенд — под «Ещё фильтры»; чипы активных фильтров. Вместо
виджета — ссылка на аккаунт. Сортировка сервера по `updated_at` не
переставляется на клиенте. Повтор только если `retry_allowed`, из
карточки задачи. Лимит окна — 7 суток (совпадает с retention Core).

### Система

Бекенды — таблица реестра `GET /system/backends` (`items[]`): имя,
тип, состояние, контракт, последняя проверка, ошибка. Ревизия SHA,
возможности адаптера и бекенда, продукты и JSON компонентов —
карточка строки. Ссылки Grafana/Loki — из `observability`.
Также сотрудники (admin), мои сессии, аудит админки. У каждой страницы
одна шапка с обновлением. Аудит: выбор сотрудника из списка, действие
из известных кодов, быстрые фильтры «Ошибки входа» и «Действия
сотрудников» в строке фильтров. Список сотрудников
показывает `PageSkeleton`, повтор при ошибке и пустое состояние с
пояснением. Отзыв сессии — диалог с текстом последствий, не кнопка
в строке без подтверждения.

## Состояния загрузки и ошибок (общие)

- Скелетон, похожий на раскладку экрана (`PageSkeleton`); при повторной
  загрузке — прежние данные с индикатором.
- Ошибка запроса → `ErrorState` с `request_id` и кнопкой «Повторить».
- 401 → выход на `/login?next=`; 403 → «Недостаточно прав» без выхода.
- Частичный ответ (`sources` с `unavailable`) → баннер над данными.
- Пустой список и недоступный источник — разные тексты: пустой список
  объясняет, что источник ответил; `unavailable` — что данных нет из‑за
  отказа, а не потому что объектов ноль.
- Хлебные крошки в шапке — ссылки на предков с разделителем `›`; текущая
  страница не дублирует заголовок `h1` отдельной ссылкой «назад».
  Код бекенда и UUID в крошках не показываются: вместо них «Подключение»,
  «Интеграция», «Операция».
- Обновление — иконка в шапке страницы со временем последней загрузки;
  источники и `observed_at` — в подсказке
  ([ADR-0021](../adr/0021-calm-interface.md)).

### Операции админки

Список `/operations/admin` с фильтрами и keyset-пагинацией;
`/operations/admin/{id}` — сохранённый результат и polling.
После потери POST-ответа UI ищет request_key через GET; повтор POST
автоматически не выполняется. Для постановки в очередь карточка
операции отдельно подтверждает enqueue; «Проверить задачу» раскрывает
Observation задачи и опрашивает её до завершения без повторного
выполнения команды.

Диалог команды показывает объект, команду, необратимость, последствия
для клиента. Секрет очищается после отправки и не сохраняется при
reload. Права UI берутся из me; сервер повторно проверяет их перед
dispatch.

### Настройки модуля

`/accounts/$accountId/widgets/$backend/$connectionId/settings` —
настройки Activity (CAS `expected_updated_at`), команды sync по
состоянию (enable **или** disable, sync/backfill; операция идёт в
фоне, результат в истории), панели (create/patch/rotate без секрета
ссылки), правила lead-status с формой и грязным состоянием,
запуски (`expected_revision`). Ошибка авторизации Core — один баннер.
Карточка подключения показывает `activity_sync` Observation (лаг,
диапазон, last_*, reauth). Ссылки Grafana/Loki, если заданы env.

## Распределение (РС-09)

В карточке `/accounts/$accountId/widgets/$backend/$connectionId` вкладка
«Распределение сделок» (`section=distribution`). Сводка показывает источник,
время наблюдения, происхождение, OAuth/webhook, effective capability,
паузы новой Core-адмиссии, связь TeamOS и независимые backlog/операции.
Очередь TeamOS обозначена unknown, её данные Core не наблюдает.

Поиск UUID и `distribution_cursor/distribution_limit` сохраняются в URL;
back/forward обновляет поисковую форму. Черновик ввода остаётся локальным
до отправки. Цепочка показывает event/operation/result/scan/consumer,
безопасные ссылки идентичностей, эффект/evidence и ошибки.
При неизвестном эффекте и незавершённых applying/confirming с фактом
попытки доступна GET-проверка, при blocked delivery —
повтор того же message_id. Нет слепой повторной команды назначения.
Команда открывает доступный с клавиатуры существующий confirm dialog;
показывает scope/последствия/следующий шаг и durable operation.

Квитанции trace-команд сохраняются отдельно по installation/command и
immutable message_id/operation_id. Неизвестный результат одного сообщения
не показывается как результат соседнего. Поле «Разрешение Core для TeamOS»
подтверждает grant, не доступность TeamOS или готовность всего подключения.

## Уточнения интерфейса от 2026-09-20

- Обзор сначала показывает четыре показателя состояния и действия по
  проблемам, затем использование, реестр бекендов и задачи. Вторичные
  показатели сохранены; ревизия и контракт раскрываются отдельно.
- Общая сводка включает все источники. Её переходы по проблемам явно
  выбирают `origin=all`, чтобы состав списка соответствовал счётчикам.
- Список аккаунтов по умолчанию выбирает `origin=real`. Выбор всех
  источников записывается как `origin=all` и не передаётся API как
  значение фильтра. `fixture` остаётся явным выбором. Старое сохранённое
  представление без `origin` открывается со всеми источниками.
- Форма сохранения представления открывается кнопкой «Сохранить вид».
  Просмотр списка представлений доступен без раскрытия формы.
- Карточка подключения содержит один центр проблем со ссылками на
  соответствующие разделы. UUID остаются в технических данных; имя
  интеграции и домен аккаунта служат основными подписями.
- Карточки и сетки допускают сжатие; длинные значения переносятся.
  На узком экране пары «поле — значение» размещаются в одну колонку,
  широкие таблицы прокручиваются внутри своего контейнера.
- Результат команды не растягивает соседние элементы панели действий.
  В компактном виде статус, классификация, дата и ошибки видны сразу;
  UUID задачи, срок повтора и источник раскрываются в «Подробности
  выполнения». Полный экран операции сохраняет все поля. Подтверждение,
  полномочия и проверка результата сохранены.
