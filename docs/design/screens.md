# Карта экранов и переходов

Разделы верхнего уровня фиксированы заданием: Обзор, Аккаунты, Виджеты,
Операции, Система. Карточка аккаунта имеет вкладки Обзор, Виджеты, Операции,
История. Настройки конкретного продукта открываются внутри его подключения.

Старая админка (`rakurs-ssd`) изучена как источник сценариев: карточка клиента
с поддоменом/ID/тарифом/датами, менеджер виджетов с действиями «Проверить»,
«Приватная интеграция», «Продлить», «История продлений», страница Activity с
полями «последний синк», «мин/макс дата в БД», «курсор», «статус синка», «текст
ошибки» и действием «Синхронизировать» (ручной диапазон до 14 дней, статусы
`success`/`failed`/`token_revoked`). Состояния подключения старой системы —
`activated`, `access_only`, `access_lost`, `not_installed`, `disabled`; они
смешивали OAuth-факт с заполнением формы установки, а проверка подключения
возвращала булев результат без классификации ошибок. Новый словарь
([states.md](states.md)) разделяет эти факты и требует классификации на
этапе 2. Тарифы, бонусы, партнёры и вход в ЛК клиента в четыре этапа не входят.

## Маршруты

| Путь | Экран | Этап |
| --- | --- | --- |
| `/login` | Вход | 1 |
| `/` | Обзор | 1 (минимум), 3 (статистика) |
| `/stats/accounts?metric=&period=` | Аккаунты показателя статистики | 3 |
| `/accounts?q=&product=&connection=&problem=&sort=&cursor=` | Список аккаунтов | 1 |
| `/accounts/:accountId` | Карточка аккаунта → вкладка Обзор | 1 |
| `/accounts/:accountId/widgets` | Вкладка Виджеты (подключения) | 1 |
| `/accounts/:accountId/widgets/:backend/:connectionId` | Карточка подключения | 1 |
| `/accounts/:accountId/widgets/:backend/:connectionId/settings` | Настройки модуля (Activity/lead-status) по продуктам и возможностям бекенда; без `settings` ссылка скрыта, неподдерживаемый модуль — «настройки недоступны» | 3–4 |
| `/accounts/:accountId/operations` | Вкладка Операции (jobs, команды, операции) | 1 (чтение), 2 (операции) |
| `/accounts/:accountId/history` | Вкладка История (аудит Core + аудит админки по объекту) | 1 |
| `/widgets` | Каталог продуктов и интеграций | 1 |
| `/widgets/:backend/:integrationId` | Карточка интеграции: параметры, сервисы, подключения, статистика | 1 (чтение), 2 (управление), 3 (статистика) |
| `/operations?status=&type=&backend=&cursor=` | Задачи и попытки по всем аккаунтам | 1 (чтение), 2 (повтор) |
| `/operations/admin?state=` | Операции админки (команды сотрудников) | 2 |
| `/system` | Реестр бекендов: статус, тип, контракт, ревизия, возможности, последний ответ, ошибка | 1–4 |
| `/system/employees` | Сотрудники и роли | 1 (admin) |
| `/system/sessions` | Мои сессии | 1 |
| `/system/audit?employee=&action=&cursor=` | Аудит действий сотрудников | 1 |

Все фильтры, сортировка и курсор пагинации живут в URL (search params).
Прямая ссылка на любой экран после входа открывает именно его; до входа —
редирект на `/login?next=`.

## Ключевые переходы

```text
Вход
  └─> Обзор ──(проблемные подключения)──> Аккаунты с фильтром problem=…
        └─> Аккаунты ──(поиск по ID / домену / ссылке)──> Карточка аккаунта
              ├─ Обзор: сводка подключений, агрегированное состояние, разбивка
              ├─ Виджеты: список подключений ──> Карточка подключения
              │     ├─ Авторизация, webhook, гранты, Activity pilot/доставка
              │     ├─ Последние jobs и ошибки
              │     └─ (этап 2) действия: проверить, reconcile, enable/disable, revoke, uninstall
              ├─ Операции: jobs аккаунта, попытки; (этап 2) операции админки
              └─ История: аудит Core по установкам + аудит админки по аккаунту
Виджеты ──> Карточка интеграции ──> список её подключений ──> Карточка аккаунта
Операции ──> Job ──> Карточка подключения / аккаунта
Система ──> Бекенд ──> ссылки в мониторинг с контекстом (этап 3)
```

## Экраны этапа 1

### Вход

Email, пароль, кнопка. Ошибка без различия причины. После входа — переход на
`next` или Обзор. Блокировка частоты попыток отображается как «Слишком много
попыток, повторите через N с».

### Обзор (минимум этапа 1)

- Блок «Бекенды»: реестр `GET /system/backends` — состояние, тип адаптера,
  контракт, ревизия, возможности адаптера/бекенда, последний успешный
  ответ, время проверки, ошибка.
- Блок «Требуют внимания»: счётчики по типам проблем из
  `GET /accounts?problem=…&limit=1` (только `total`), каждый — ссылка на список
  с фильтром. Если источник `unavailable` — счётчик «—» и баннер.
- Блок «Последние ошибки задач»: 10 последних `failed`/`dead` jobs.

Полная статистика — этап 3; здесь только то, что уже есть в списках.

### Аккаунты

- Поле поиска принимает: числовой `account_id`; поддомен `example`; домен
  `example.amocrm.ru` / `example.kommo.com`; полную ссылку
  `https://example.amocrm.ru/leads/detail/123` (извлекается домен). Нормализация
  — на сервере, клиент отправляет строку как есть.
- Фильтры: продукт (интеграция), состояние подключения, тип проблемы, метка
  происхождения (`real`/`fixture`).
- Колонки: аккаунт (ID, домен), подключения (по одному бейджу на интеграцию с
  каноническим состоянием), агрегированное состояние, последняя активность
  (`max(updated_at)` по подключениям), источник/свежесть.
- Пагинация курсором, размер страницы 25/50/100, ограничена сервером.
- Баннер «Часть источников недоступна» из `sources`.
- Пустой результат отличает «ничего не найдено» и «источник недоступен».

### Карточка аккаунта — Обзор

Шапка: `account_id`, домены (все, если у разных установок разные), число
подключений, агрегированное состояние с разбивкой, метка происхождения.
Тело: по карточке на каждое подключение — интеграция, состояние, авторизация,
webhook, последняя ошибка, `observed_at`. Клик — карточка подключения.
Блок «Подписка» (`GET /accounts/{id}/subscription`): план, состояние
(`active`/`trial`/`expired`/`cancelled` и `unknown` с `raw`), срок,
возможности. Пустой ответ — «данные подписки недоступны», а не «нет
подписки»; отказ источника не скрывает другие блоки.

### Карточка подключения

Секции:

1. **Идентификация**: интеграция (code), `installation_id`, `account_id`,
   домен, `installed_by` (ID пользователя amoCRM), даты.
2. **Состояние**: подключение, авторизация (с модификатором `unverified`),
   webhook (статус, события, `checked_at`, `last_error`), гранты сервисов.
3. **Activity** (если грант есть): pilot, последние команды доставки,
   синхронизация — `unknown` с причиной до этапа 3.
4. **Последние задачи**: 20 jobs с попытками (раскрытие).
5. **История**: аудит Core по `installation_id`.
6. **Действия** (этап 2): недоступные скрыты по правам, доступные — с диалогом
   области воздействия.

Каждая секция — независимое наблюдение: отказ одной не скрывает другие.

### Карточка аккаунта — Операции и История

Операции: таблица jobs аккаунта с фильтром по статусу/типу, раскрытие
попыток. История: объединённая лента (Core audit по установкам аккаунта + admin
audit по объектам аккаунта), с указанием источника записи.

### Виджеты

Список интеграций: code, состояние, сервисы с грантами, число подключений по
состояниям, `redirect_uri` (host), события webhook. Секретов и `client_id`
целиком нет: показывается только `client_id` (это публичный UUID интеграции
amoCRM; допустимо), `client_secret` — только `key_version` и `updated_at`.

### Операции (глобальные)

Jobs всех аккаунтов: фильтр статуса/типа, сортировка по `updated_at`,
ссылка на подключение. Лимит окна — 7 суток (совпадает с retention Core).

### Система

Бекенды — таблица реестра `GET /system/backends` (`items[]`): код и
отображаемое имя, тип адаптера, продукты, состояние, contract version,
ревизия, возможности адаптера и бекенда, компоненты, последний успешный
ответ (`observed_at`, может быть «—»), время проверки (`checked_at`),
ошибка (`code` + сообщение). Ссылки Grafana/Loki — из `observability`.
Также сотрудники (admin), мои сессии, аудит админки.

## Состояния загрузки и ошибок (общие)

- Скелетон для первичной загрузки; при повторной — прежние данные с индикатором.
- Ошибка запроса → `ErrorState` с `request_id` и кнопкой повтора.
- 401 → выход на `/login?next=`; 403 → «Недостаточно прав» без выхода.
- Частичный ответ (`sources` с `unavailable`) → баннер над данными.

### Уточнение этапа 1 (2026-09-13)

Вкладка операций аккаунта получает единый список из
`/api/v1/accounts/{account_id}/jobs`; фильтры и курсор сохраняются в URL.
Кнопки продолжения и сброса доступны как в глобальном списке задач.
Фильтр продукта аккаунтов использует сервисы каталога; карточка интеграции
передаёт отдельный `integration_id` и `backend`.

## Этап 2

- Карточка подключения: диалог управления с областью воздействия,
  независимая проверка OAuth, pilot и доступные повторы доставок.
- Интеграции: создание, изменение redirect/events, ротация секрета,
  включение/отключение всей интеграции, гранты сервисов.
- Операции: список `/operations/admin` с фильтрами и keyset-пагинацией;
  `/operations/admin/{id}` — сохранённый результат и polling.
- Диалог показывает объект, команду, необратимость, последствия для
  клиента. Секрет очищается после отправки и не сохраняется при reload.
- Права UI берутся из me; сервер повторно проверяет их перед dispatch.
- После потери POST-ответа UI ищет request_key через GET; повтор POST
  автоматически не выполняется.
- Для постановки в очередь карточка операции отдельно подтверждает
  enqueue; «Проверить задачу» раскрывает Observation задачи и опрашивает
  её до завершения без повторного выполнения команды.

## Этап 3

- `/` — блок статистики `GET /stats?period=` (24h/7d/30d в URL). Ноль —
  «0», отсутствие — «—». Показатели ведут на `/stats/accounts`.
- `/stats/accounts?metric=&period=` — список аккаунтов показателя.
- `/accounts/$accountId/widgets/$backend/$connectionId/settings` —
  настройки Activity (CAS `expected_updated_at`), команды sync
  (enable/sync/backfill/disable; «202 не означает завершение»), панели
  (create/patch/rotate без секрета ссылки), правила и запуски
  lead-status (`expected_revision`).
- Карточка подключения: реальный `activity_sync` Observation (лаг,
  диапазон, last_* , reauth). Ссылки Grafana/Loki, если заданы env.
- Сохранённые представления: FilterBar аккаунтов и списка статистики;
  личные и общие (`views:write` у operator+).
