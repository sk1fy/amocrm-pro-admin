# ADR 0024. Сессии менеджеров в Admin

## Контекст

Технический кабинет уже проверяет сотрудников и хранит сессии в Admin.
Демонстрационные данные менеджеров существуют отдельно в интерфейсе.
Для V1 менеджерский кабинет открывается на отдельном хосте.

## Решение

Переиспользуем учётную запись и проверку пароля сотрудника. В PostgreSQL
храним audience каждой сессии и отдельные гранты сотрудников. HTTP API
выбирает кабинет по Host, проверяет audience по записи сессии и читает
действующие права на каждом запросе менеджера. У каждого кабинета свой
Origin для CSRF и свой host-only cookie.

Первоначальный доступ выдаёт оператор Admin CLI одному выбранному
активному сотруднику с паролем. Выдача и запись аудита происходят в одной
транзакции. Дополнительные назначения выполняются через управление
сотрудниками после его подключения.

## Последствия

Сессии, созданные до миграции, получают audience `core-admin`.
Отзыв своей сессии ограничен текущим кабинетом. Системный отзыв сессий
сотрудника распространяется на оба кабинета. Смена технической роли
отзывает сессии технического кабинета. Сборка менеджеров имеет
собственную точку входа и использует только менеджерский API.
