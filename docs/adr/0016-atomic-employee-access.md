# ADR-0016: атомарные изменения доступа сотрудников

Статус: принято. Дата: 2026-09-19.

## Контекст

AUD-02/04: чтение сотрудника перед PATCH позволяло перезаписать
конкурентную блокировку старым статусом. Отдельные commit изменения,
отзыва сессий и аудита оставляли частичный результат при сбое.

## Решение

Сервис `employees.Access` объединяет мутацию, отзыв сессий и `RecordTx`
в одну транзакцию Admin DB. PATCH читает строку с `FOR UPDATE`, сохраняет
непереданные поля и строит diff по защищённому чтению. Ошибка любого
шага откатывает операцию. Создание, ручной отзыв сессий и logout имеют
такую же границу транзакции. Внешних вызовов внутри нет.

Login limiter хранит не более 10 000 счётчиков фиксированного размера.
Текущие счётчики не вытесняются: при заполнении новые ключи получают
отказ до следующей минуты. После отказа по IP email не добавляется.
Таблица очищается один раз при смене минутного окна.

Ошибки credentials сохраняют единый 401; ошибки инфраструктуры дают
безопасный 500 с request_id и отдельное сообщение интерфейса.

## Отклонённые варианты

Отдельная запись аудита после commit не гарантирует полноту журнала.
Вытеснение активных ключей limiter позволяло бы сбрасывать счётчики.
Распределённая очередь для записей одной Admin DB не требуется.

## Последствия

Операция доступа может завершиться ошибкой при отказе журнала; частичный
результат не фиксируется. Ёмкость limiter ограничивает доступность
новых ключей при атаке до конца минутного окна. Лимитер process-local;
правила reverse proxy и число API replicas требуют отдельной проверки.
