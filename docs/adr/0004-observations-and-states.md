# ADR-0004: Наблюдения, свежесть и словарь состояний

Статус: принято. Дата: 2026-09-12.

## Контекст

Админка показывает данные из нескольких бекендов с разной доступностью.
Задание требует различать «неизвестно», «данные устарели», «отключено», «нужна
авторизация» и «временная ошибка», а также показывать источник и время
наблюдения.

## Решение

1. **Каждый факт о внешнем объекте — это наблюдение.** Тип
   `Observation<T>` в Admin API и frontend:

   ```json
   {
     "source": "core",
     "observed_at": "2026-09-12T15:40:12Z",
     "freshness": "fresh | stale | unavailable | unknown",
     "error": { "code": "backend_unavailable", "message": "…" },
     "data": { }
   }
   ```

   `data` может отсутствовать при `unavailable`/`unknown`. Никогда не
   подставляется значение по умолчанию вместо отсутствующего факта.

2. **Свежесть** определяется Admin API, а не бекендом: `fresh` — ответ получен
   в текущем запросе; `stale` — отдан из кеша admin-api старше порога (кеш
   появится не раньше этапа 3); `unavailable` — адаптер вернул ошибку/таймаут;
   `unknown` — бекенд не заявляет такую возможность или данных нет по природе
   (например, sync status Activity до подключения источника на этапе 3).

3. **Ответы списков содержат `sources`** — массив состояний бекендов,
   участвовавших в запросе: `{ backend, status: available|degraded|unavailable,
   observed_at, error }`. Список с `sources[*].status=unavailable` — это
   частичный результат, интерфейс показывает баннер.

4. **Словарь состояний** — единственный источник истины в
   [states.md](../design/states.md). Бекендные значения (`installations.status`
   и т. п.) отображаются в канонические состояния в адаптере, а не во frontend.
   Неизвестное бекендное значение → `unknown` с оригиналом в `raw`.

5. **Нулевое значение ≠ отсутствие данных.** Счётчики возвращаются как
   `{ "value": 0 }` или `null`; frontend показывает «—» для `null` и «0» для 0.

## Последствия

- В контрактах нет «плоских» статусов без обёртки наблюдения для данных,
  полученных от бекендов.
- Компонент `Observation` во frontend обязан выводить `observed_at` и источник
  (в подсказке) и особый вид для `stale`/`unavailable`/`unknown`.
- Тесты адаптеров проверяют маппинг каждого бекендного значения в канонический
  словарь и поведение при неизвестном значении.
