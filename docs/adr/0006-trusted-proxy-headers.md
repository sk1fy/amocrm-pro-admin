# ADR-0006: Доверие заголовкам прокси

Статус: принято. Дата: 2026-09-13.

## Контекст

В compose перед Admin API всегда стоит nginx frontend: он проксирует `/api`
и передаёт `X-Real-IP` и `X-Forwarded-For` (см. `frontend/nginx.conf`).
`RemoteAddr` всех запросов UI содержит адрес контейнера nginx, поэтому и лимит
входа по IP, и аудит (`auth.ClientIP`) видят один и тот же адрес и не
различают клиентов. При этом заголовки прокси подконтрольны клиенту, если
Admin API доступен напрямую (например, опубликованный порт `127.0.0.1:8090`).

## Решение

- `auth.ClientIPFrom(r, trustProxy)` — единая точка определения IP клиента.
  При `trustProxy=true` берётся первый разбираемый `netip.ParseAddr` адрес из
  `X-Forwarded-For` (опциональный порт отбрасывается), затем `X-Real-IP`,
  иначе `RemoteAddr`; частные и loopback-диапазоны не фильтруются.
- `auth.ClientIP(r)` сохраняет прежнее поведение и не читает заголовки; это
  умолчание для любого окружения.
- Доверие включается только переменной `TRUST_PROXY_HEADERS=true`
  (`platform/config`, по умолчанию `false`). Compose админки выставляет
  `true`, потому что nginx в нём есть всегда.
- Один и тот же результат используется лимитером входа, аудитом и полем `ip`
  сессии — расхождений между ними быть не должно.

## Отклонённые варианты

- **Доверять `X-Forwarded-For` всегда** — при прямом доступе к API клиент сам
  задаёт заголовок, обходит лимит по IP и подменяет IP в аудите; небезопасное
  умолчание запрещено.
- **Полагаться только на `real_ip`-модуль nginx** — он подменяет
  `$remote_addr` в логах самого nginx, но Admin API всё равно не знает, можно
  ли верить заголовку. Решение о доверии должно быть явным на стороне
  приложения.
- **Список доверенных прокси в конфигурации** — для текущего контура прокси
  один; отдельная модель доверия по адресам преждевременна (нужна, если
  появится балансировщик перед nginx).

## Последствия

- Окружения, где API стоит за прокси, обязаны выставить
  `TRUST_PROXY_HEADERS=true`; иначе лимит входа и аудит останутся на IP
  прокси. Окружения без прокси обязаны оставить `false`.
- Доверие левому значению XFF предполагает, что цепочку формирует прокси, а
  не клиент. Bundled nginx добавляет `$remote_addr` к клиентскому заголовку
  (`$proxy_add_x_forwarded_for`); при выносе стенда наружу прокси должен
  перезаписывать `X-Forwarded-For`, иначе клиент подставит левое значение.
- Лимитер входа по-прежнему ограничивает и IP, и email, поэтому подмена IP не
  отменяет ограничение по email.
