# ADR-0025. Менеджерский BFF и операции Platform V1

## Контекст

Admin владеет доступом менеджеров. Platform владеет продуктами,
установками, исходами команд и их внешними эффектами. Сетевой обрыв
между этими сервисами может скрыть уже выполненную команду.

## Решение

Admin пинит [машинный контракт P01](../../backend/api/platform-v1-openapi.yaml)
из ревизии Core `70bfdf938006a51203f65a765a644273b94e6ede`. Тест проверяет
SHA-256, а `make platform-contract-check` сверяет сгенерированный код.
Клиент подключается по TLS 1.3 к закрытому DNS-имени Platform через
заданный CA. Клиентский сертификат использует единственный URI SAN
`spiffe://amocrm-pro/manager-bff`. Редиректы запрещены.

Каждый сетевой вызов использует новый `X-Platform-Actor` с актуальной
сессией, упорядоченными grants и их версией из одного запроса к БД.
При изменении грантов версия увеличивается в той же транзакции.
Первоначальное значение для существующих сотрудников равно 1.

Перед отправкой команда получает устойчивый UUID. Транзакция Admin
сохраняет ID сотрудника, ID исходной сессии, ключ идемпотентности,
команду, цель, предусловие, хеш нормализованного тела и запись аудита.
Один ключ на сотрудника соответствует одному набору параметров.
Пароли, actor envelope, исходный payload и ответ Platform не хранятся.

Go-воркер использует ограниченный lease PostgreSQL и читает receipt
по ID команды, затем операцию при наличии её ID. Он проверяет исходную
сессию, которая не продлевается фоновой сверкой. Browser GET проверяет
текущую менеджерскую сессию, право чтения и владельца intent, затем
читает живой результат. Receipt 404 оставляет исход неизвестным.
Повтор действия возможен только по явному идентичному запросу
пользователя после сверки, с прежними ключом, UUID, payload и версией.
Клиент HTTP автоматически не повторяет мутации.

## Отклонённые варианты

У технических операций Admin свой исполнитель, набор прав и формат
результата. Общая таблица смешала бы технические и менеджерские
операции. BFF повторно использует PostgreSQL, аудит и фоновые lease,
хранит менеджерские intent в отдельной таблице и делегирует эффекты
Platform. Брокер сообщений и локальная копия продуктовых данных не нужны.

## Последствия

Потеря ответа или рестарт Admin не меняют ID команды. Без текущего
доступа Admin не возвращает исход. Недоступность Platform не блокирует
вход в менеджерский или технический кабинет. Срок хранения intent
надо согласовать со сроком хранения ключей Platform перед введением
очистки. Техническая политика retention не удаляет менеджерские intent.
