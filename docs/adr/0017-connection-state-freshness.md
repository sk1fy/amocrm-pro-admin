# ADR-0017: актуальность состояния установок

Дата: 2026-09-19. Статус: принято.

## Контекст

Состояние установки, локальные credentials, доступ amoCRM и доступность Core —
разные факты. Открытые списки не обновлялись, а ручная check-квитанция могла
оставаться в Admin DB после новой OAuth-сессии.

## Решение

Core возвращает optional `authorization_check` в summary установки. При
наличии поля именно Core определяет classification, observed_at и freshness.
Значение unknown от нового Core никогда не заменяется старой Admin-квитанцией.
Fallback `LatestCheck` применяется только к старому Core без нового поля.
Недоступный Core даёт unavailable и для проверки. Срок свежести 5400 секунд
задаёт Core; поле `fresh_for_seconds` показывается пользователю. Для старого
Core сохраняется прежний fallback 15 минут.

Общий QueryClient включает polling только видимой активной вкладки backend-данных: карточки,
обзор и реестр 15 секунд, аккаунты 90 секунд, активная операция 1,5 секунды.
Потеря фокуса окна (blur) также приостанавливает polling.
Возврат фокуса/видимости запускает refetch. Сессии и справочники сохраняют
прежнее поведение. Терминальные операции инвалидируют связанные данные на
любом экране. Если запрос начался до завершения команды, после его завершения
выполняется новый запрос; одновременно два запроса одного ключа не идут.
Ошибки обновления явно подписаны рядом с прежним снимком.

`verification` — независимый фильтр. Адаптер передаёт его Core для SQL
pushdown. Старые источники могут игнорировать параметр: в таком случае
обход ограничен четырьмя native pages на источник. Пустая отфильтрованная
страница сохраняет continuation; `total=null` означает неизвестное количество.
Курсор содержит позиции источников и scope фильтра, без offset и данных
клиента. Row cursor сохраняет native order. Для нескольких источников
выбранные аккаунты объединяются через ограниченный `GetAccount`; один
детерминированный источник владеет выдачей аккаунта, чтобы исключить дубли.

## Отклонённые варианты

- Перекодировать проверку в `installations.status`.
- Считать unknown успешной проверкой или выводить 0 вместо отсутствия счётчика.
- Проверять amoCRM при каждом GET интерфейса.
- Полный scan всех аккаунтов каждые 90 секунд ради verification-фильтра.

## Последствия

v1 обратно совместим: новые поля optional; нет новых таблиц Admin DB.
Старый источник может дать неполную страницу с продолжением. Поиск по
verification в нескольких источниках требует дополнительных bounded чтений
карточек. Автоматическое расписание Core включается отдельным feature flag;
локальный выпуск не включает production rollout.
