# ADR-0002: Стек frontend

Статус: принято. Дата: 2026-09-12.

## Контекст

Frontend — внутренний инструмент для небольшой команды. Приоритеты: прямые
ссылки на аккаунт/подключение, фильтры в URL, честное отображение состояний,
простая поддержка другими агентами. Laravel/Filament исключены заданием.

## Решение

- **React + TypeScript (strict)**, сборка **Vite**.
- **TanStack Router** — типизированные маршруты и search params (фильтры и
  пагинация живут в URL).
- **TanStack Query** — загрузка, кеш, повторные запросы, состояния
  `loading/error/stale` на уровне данных.
- **CSS Modules + CSS custom properties**, без UI-кита и CSS-фреймворка.
  Небольшой собственный набор компонентов: `StatusBadge`, `Observation`,
  `DataTable`, `FilterBar`, `EmptyState`, `ErrorState`.
- **Vitest + Testing Library** для unit/компонентных тестов; **Playwright**
  для сквозных сценариев (добавляется на этапе 1 для сценария поиска).
- Пакетный менеджер — **npm** (есть на машинах команды, без дополнительной
  установки). Lockfile коммитится.
- Точные версии фиксируются при старте реализации этапа 1 командой
  `npm view <pkg> version` и записываются в `frontend/package.json`; в
  документацию версии не копируются, чтобы не устаревать.

## Почему без UI-кита

Экранов немного, а требования к отображению состояний специфичны
(«неизвестно» ≠ «ошибка», обязательное время наблюдения). Собственные компоненты
проще держать в соответствии со [словарём состояний](../design/states.md), чем
переопределять чужую тему. Если позже понадобится богатый набор (таблицы с
настраиваемыми колонками на этапе 3), допустим headless-набор (например,
TanStack Table) — без визуальной темы.

## Последствия

- Все строки интерфейса — на русском; идентификаторы состояний — английские
  константы из `states.md`.
- Любое отображение состояния проходит через `StatusBadge`/`Observation`;
  «сырые» строки статусов бекенда в JSX запрещены.
- Query keys строятся из URL-параметров; нет дублирования фильтров в локальном
  состоянии.
