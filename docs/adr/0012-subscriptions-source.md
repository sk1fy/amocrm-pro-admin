# ADR-0012: Источник подписок

Статус: принято, 2026-09-13.

## Контекст

Подписка — коммерческий факт об аккаунте: тариф, срок действия и
возможности, предоставленные планом. Технический грант сервиса
(`Grant`) отвечает за другое: включён ли сервис интеграции у установки.
У них разные жизненный цикл, владелец и полномочия, поэтому подписка не
может быть частью гранта или агрегата аккаунта. До этапа 4 карточка
аккаунта не показывала подписку, а отсутствие источника нельзя было
честно отличить от «подписки нет».

## Решение

1. `Subscription{Plan, State, ExpiresAt, Capabilities}` — отдельная
   модель адаптера. Опциональный интерфейс
   `SubscriptionBackend.GetSubscription(ctx, actor, accountID)` и
   возможность `subscriptions`; проверяются вместе через
   `AsSubscription`. Бекенд без возможности остаётся допустимым.
2. Канонические состояния `active`/`trial`/`expired`/`cancelled`;
   значения бекенда переводятся адаптером через `MapSubscriptionState`,
   неизвестное значение → `unknown` + `Raw`.
3. Admin API: `GET /api/v1/accounts/{account_id}/subscription` под
   правом `accounts:read`. Опрашиваются только способные бекенды;
   ответ — `{items: Observation<Subscription>[], sources[]}`. Пустой
   `items` при отсутствии способных бекендов или факта означает «данные
   подписки недоступны» (`unknown`), никогда «нет подписки» и никогда
   не ошибку. Упавший способный бекенд виден как наблюдение/источник
   со свежестью `unavailable`.
4. Не реализованы: платежи, продления, каталог тарифов и поштучный
   учёт мест. Кеша нет, свежесть передаётся через `Observation`. Core
   сегодня возможность не объявляет, поэтому реальный стек честно
   показывает unknown; fixture даёт отмеченные данные для части
   аккаунтов.

## Отклонённые варианты

- Подписка внутри `Grant` или агрегата аккаунта: разные жизненный цикл
  и владелец, смешение коммерческого и технического фактов.
- Отдельный микросервис подписок: новая инфраструктура ради одного
  чтения, которого у бекенда может не быть вовсе.
- Вычисление подписки из jobs/использования: нет надёжного источника,
  результат выдавался бы за факт.

## Последствия

Карточка аккаунта получает блок «Подписка» с честным unknown без
источника. Подключение реального источника — объявление возможности и
реализация интерфейса без изменения контракта v1
([ADR-0011](0011-adapter-contract-v1.md)).
