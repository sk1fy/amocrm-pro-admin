# ADR-0015: Диагностика подключения в интерфейсе

Статус: принято. Дата: 2026-09-14.

## Контекст

Карточка подключения отдаёт независимые Observation: установка, OAuth,
проверка amoCRM, webhook, Activity, sync, jobs, аудит. Показ всех фактов
подряд смешивает итог, первопричину и технические детали. Администратор
видит «аккаунт в порядке» при устаревшей проверке или `core admin
authentication failed`.

Агрегат аккаунта уже считается в Admin API. Итог одного подключения до
этого patch в API не существовал, а расширять контракт ради подписей UI
не требовалось: все нужные факты уже есть в карточке.

## Решение

1. **Итог подключения считается в UI** из Observation карточки. Домен
   `connection_health`: `working`, `working_with_warnings`, `needs_action`,
   `unavailable`. Рядом 1–3 причины. Это отображение, не поле сортировки
   и не замена `installations.status`.

2. **Вкладки карточки живут в URL** (`section`): состояние, авторизация,
   webhook, Activity, задачи, история. Сводка и центр проблем всегда
   сверху. Если `section` нет, открывается первый проблемный раздел.

3. **Связанные unavailable** с одной безопасной ошибкой Core
   (`core admin authentication failed`) показываются как один инцидент.
   Зависимые блоки не дублируют красный баннер, а ссылаются на него.

4. **Команды контекстны.** Основная — проверка подключения. Включить /
   выключить и пилот — по состоянию. Revoke и uninstall — меню «Ещё» и
   опасная зона, каждое со своим подтверждением.

5. **Источник Observation** на карточке показывается один раз в сводке.
   В блоке — только если отличается от `backend` страницы.

## Отклонённые варианты

- Новый endpoint агрегата подключения: дублирует карточку, задерживает UX.
- Только якоря без вкладок: длинный поток данных сохраняется.
- Командная палитра с поиском: для текущего набора команд избыточна.

## Последствия

- Словарь состояний дополняется `connection_health` и пользовательскими
  подписями доставки.
- Frontend содержит таблицу расшифровок job/audit/webhook; неизвестный
  код остаётся виден как `raw`.
- E2E, завязанные на «источник:» внутри каждого блока карточки, нужно
  смотреть в сводке или технических подробностях.
