# ADR-0008: курсоры истории и операций аккаунта

Статус: принято. Дата: 2026-09-13.

## Контекст

История объединяет аудит подключений Core и admin DB. Операции аккаунта
объединяют задачи нескольких подключений. Фильтрация первых страниц
источников после загрузки теряла старые записи. Клиентская пагинация
также не могла использовать продолжение каждого подключения.

## Решение

Admin API выполняет слияние ограниченных страниц источников.
`GET /api/v1/accounts/{account_id}/jobs` принимает `status`, `type`,
`limit`, `cursor`; каждая задача содержит `backend` для последующих
запросов и ссылок. История сохраняет существующий маршрут.

Адаптеры возвращают внутренний `Cursor` каждой строки jobs/audit.
Core-адаптер строит позицию по контракту v1: RFC3339Nano UTC и ID,
закодированные base64url. Jobs используют `updated_at`, аудит —
`created_at`. Это знание локализовано в Core-адаптере; HTTP DTO
не сериализуют внутренний курсор строки. Admin-аудит формирует позицию
в собственном хранилище. Fixture-адаптер использует ID строки.

Общий курсор содержит версию, область применения (аккаунт и фильтры)
и последние выданные позиции источников. В нём нет строк аудита,
содержимого задач и учётных данных. Передаются только курсоры реально
выданных строк; непрочитанный остаток страницы читается заново после
последней выданной позиции. Позиция исчерпанного источника сохраняется,
чтобы он не начинал заново с первой страницы.

За запрос читается не более `limit` записей каждого источника;
результат ограничен общим `limit` (1–100, по умолчанию 25).
Порядок — время по убыванию, затем идентификатор источника; внутри
источника сохраняется его порядок, включая одинаковые timestamps.
Курсор другой области или неправильного формата возвращает 400.

Ошибки источников сохраняются в `sources`. Их позиции не продвигаются.
После восстановления можно повторить текущую страницу. Слияние не даёт
транзакционного snapshot нескольких бекендов: новые и обновлённые задачи
подчиняются обычной семантике keyset по `updated_at`.

## Отклонённые варианты

- OFFSET или загрузка всей истории: неограниченный объём и нестабильность.
- Хранение непрочитанных строк в курсоре: размер URL и раскрытие данных.
- Пагинация независимо на frontend: дублирование логики слияния и ошибок.

## Последствия

Адаптер обязан выдавать позицию каждой строки и сортировать страницы
по указанному времени. Изменение кодировки курсора Core требует изменения
только его адаптера и контрактных тестов. Смена размера страницы не меняет
позицию. Старые курсоры истории прототипа не поддерживаются: нужно удалить
параметр `cursor` из URL.
