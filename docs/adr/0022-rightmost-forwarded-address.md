# ADR-0022. Правое значение X-Forwarded-For

Статус: принято. Дата: 2026-11-07. Заменяет в
[ADR-0006](0006-trusted-proxy-headers.md) правило выбора адреса
из `X-Forwarded-For`; остальные решения ADR-0006 действуют.

## Контекст

ADR-0006 брал первый разбираемый адрес из `X-Forwarded-For`. Это верно,
только если цепочку целиком пишет прокси. Фактические цепочки:

| Окружение | Путь `/api` | Кто пишет `X-Forwarded-For` |
| --- | --- | --- |
| `make up` | клиент → nginx frontend → Admin API | nginx: `$remote_addr`, перезапись |
| prod-оверлей | клиент → reverse proxy оператора → `127.0.0.1:8090` | прокси оператора |

В prod `/api/` идёт мимо nginx frontend прямо на Admin API: между
клиентом и API ровно один прокси. Распространённая настройка nginx
`$proxy_add_x_forwarded_for` дописывает адрес клиента к заголовку,
который прислал сам клиент. Левое значение тогда задаёт клиент: он
обходит лимит входа по IP, подменяет IP в аудите и сессиях и может
заполнить таблицу лимитера (10 000 ключей), после чего вход
отклоняется всем до конца минуты.

## Решение

- При `TRUST_PROXY_HEADERS=true` `auth.ClientIPFrom` берёт последний
  элемент последней непустой строки `X-Forwarded-For` — адрес, который
  записал единственный доверенный прокси. Элементы левее игнорируются.
- Если последний элемент не разбирается как IP (пустой, `unknown`,
  мусор), используется `RemoteAddr`. Переход к элементам левее
  запрещён: их задаёт клиент.
- `X-Real-IP` используется только при отсутствии `X-Forwarded-For`;
  оба наших прокси выставляют `X-Forwarded-For`, поэтому это запасной
  путь для прокси, который пишет только `X-Real-IP`.
- Число доверенных хопов не настраивается: в обоих окружениях прокси
  один. Внешний прокси оператора обязан перезаписывать заголовок
  (`proxy_set_header X-Forwarded-For $remote_addr;`); при дописывании
  результат тот же, но перезапись не зависит от этого ADR.
- Email при входе ограничен 254 символами: длиннее — тот же ответ
  «неверные учётные данные» без запроса к БД; ключ лимитера и значение
  аудита усекаются до 254 символов.

## Отклонённые варианты

- **Левое значение (ADR-0006)** — подконтрольно клиенту при
  дописывающем прокси.
- **Настраиваемое число хопов (`TRUSTED_PROXY_HOPS`)** — нужно только
  при нескольких прокси подряд; сейчас прокси один, а лишняя настройка
  с неверным значением снова отдаёт выбор адреса клиенту. Вернуться,
  если перед прокси оператора появится балансировщик или CDN.
- **Список доверенных сетей прокси** — тот же довод, что в ADR-0006.

## Последствия

- Если перед прокси оператора появится ещё один прокси, лимит входа
  и аудит увидят адрес промежуточного прокси. Такой контур требует
  нового ADR (число хопов или список доверенных сетей).
- Прямой доступ к Admin API при `TRUST_PROXY_HEADERS=true` по-прежнему
  позволяет задать адрес заголовком; порт публикуется только на
  loopback, правило ADR-0006 о `false` без прокси сохраняется.
- Тест `auth/sessions_test.go` закрепляет: подделанное левое значение
  не влияет на результат, мусорное правое значение даёт `RemoteAddr`.
