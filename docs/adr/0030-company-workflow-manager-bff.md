# ADR-0030. Компании и workflow через manager BFF

## Контекст

Platform владеет проекциями и сохранёнными workflow. Принятая ревизия
`6e62a610b8c5935cd188c738e9afdd0cdccd9b45` предоставляет пять операций.
Компания может не иметь runtime account; настройки требуют catalog.manage
без скрытого clients.read. Карточка продукта имеет независимую версию.

## Решение

Расширить существующий manager endpoint registry, wire transport и intent.
Закрепить точные байты схемы и генератор 2.8.2. Включить новый command kind
в CHECK существующего журнала миграцией 000012. Browser проверяет DTO на
границе, различает CompanyProjectionId, AccountId и ProductId. Компании
живут в разделе Клиенты, workflow в разделе Виджеты, включая прямую
ссылку по известному product ID для catalog-only сотрудника.

Неизвестный исход сохраняет сериализованное тело, ключ и версию. Receipt
читается с текущими grants и проверкой владельца, затем точный replay
возвращает исходный результат. Явное применение после конфликта создаёт
новую команду. Источник в PUT подтверждает текущую фиксированную привязку.

## Отклонённые варианты

Прямой Core listener, второй журнал команд, компании как фиктивные runtime
accounts и выбор источника браузером нарушают владение или идентичность.

## Последствия

Сохранение не создаёт сделки. Частичный/устаревший источник видим отдельно
от отсутствия снимка. Реальная цепочка и полный make check остаются gate
приёмки; наличие исходников не подтверждает выпуск.
