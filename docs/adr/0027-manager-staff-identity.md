# ADR-0027. Менеджерские identities и атомарный доступ

## Контекст

Пятый раздел кабинета управляет сотрудниками без участия Platform.
Техническая роль и менеджерские grants относятся к разным кабинетам.
Новая identity из приглашения не должна получить технические права.
Параллельные изменения не должны удалить последнего администратора.

## Решение

Непустой набор grants разрешает менеджерский вход активной identity
с паролем. Отдельного флага менеджерского доступа нет.
`technical_access` сохраняет технический вход существующих записей.
Приглашение создаёт passwordless identity с `technical_access=false`.
Core проверяет этот признак при входе, чтении сессии и свежем RBAC.

`employees.Access` владеет транзакцией. Bootstrap, менеджерская запись
и техническое обновление берут `manager_grants` в режиме
`SHARE ROW EXCLUSIVE` перед блокировками employees. Проверка последнего
администратора учитывает активность, пароль и `staff.manage`.
Сессия и grants инициатора перечитываются под этой блокировкой раньше
квитанции и версии цели. Аудит и безопасная квитанция коммитятся
с эффектом. CLI использует тот же `Access.Update`.

Приглашение хранит только хеш токена. Однократная ссылка передаёт
токен в URL-фрагменте. Квитанция хранит безопасный Staff DTO без ссылки.
Точный повтор приглашения сообщает `link_unavailable`; перевыпуск
требует новой команды и отзывает прежний токен. Принятие и перевыпуск
сериализуются с изменениями доступа. Принятие принимает UUID команды.
Точный повтор с тем же токеном, ключом и паролем возвращает прежний успех.
Пароль сверяется с существующим Argon2-хешем; быстрый хеш пароля
в квитанции не хранится. Другая команда не потребляет токен повторно.

Менеджерский отзыв имеет явный audience `managers`. Глобальный disable
сохраняет широкую область отзыва; техническая смена роли сохраняет
менеджерские сессии. Cursor подписан HMAC с разделением назначения
от хеша текущей сессии, связан с субъектом, версией прав и фильтрами.

## Отклонённые варианты

Флаг `manager_enabled` дублирует grants и создаёт противоречивые состояния.
Общий отзыв сессий закрывает технический кабинет без соответствующей
команды. Сохранение plaintext приглашения нарушает серверную границу
секретов. Дополнительный секрет окружения для cursor не требуется.

## Последствия

При потере первого ответа оператор перечитывает сотрудника и явно
перевыпускает приглашение. Доставка сообщений остаётся ручной.
После технического disable последнего администратора API возвращает
конфликт. Down запрещён при manager-only identities, приглашениях или
квитанциях, чтобы старый бинарь не открыл технический доступ.
