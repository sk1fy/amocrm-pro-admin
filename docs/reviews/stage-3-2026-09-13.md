# Проверка этапа 3 — 2026-09-13

## Summary

Прочитаны план этапа 3, стайл-гайд, ADR-0010 и Core ADR-0028, затем
сверка с рабочим деревом Admin `feature/stage-3-modules` и Core
`feature/admin-activity` (незакоммиченные изменения относительно
`f3cc3b5` / `6f1a19c`). Принципал Activity (`Kind=operator`,
`actor_id=0`, `CheckDelegation`, секреты панелей не уходят в admin
JSON) и RBAC этапа 3 в целом соответствуют ADR. Приёмка на fixture
e2e зелёная, но живой контракт Core расходится с Admin-адаптером:
статистика, конфликт CAS без текущих значений, сотрудники панелей,
backfill `from`/`to` и поля запусков lead-status. Команды Activity
вызываются внутри SQL-транзакции квитанции Core.

## Issues

### Issue 1 -- Severity: bug
- File: `/Users/nikpeskov/Projects/amocrm-pro/internal/adminread/types.go:322`
- Description: JSON сводки статистики Core не совпадает с тем, что
  читает Admin-адаптер. Core отдаёт `period_events.connected`,
  `latency.p50_ms`, `auth_problems_count`, `from`/`to`, элементы
  `connections[].integration_code`. Админский клиент ждёт плоские
  `connected`, `latency_p50_ms`, `auth_problems`, `period_start`/
  `period_end`, `connections[].product` и `last_use_at`. На живом
  Core показатели периода станут `null` («—»), хотя источник вернул
  числа, включая настоящий ноль. Fixture Demo сериализует форму Admin,
  поэтому e2e `stat-Отключения=0` / `stat-Задержка p50=—` проходит
  без живого контракта. Поле `last_use_at` из ADR-0010 и
  `data-sources.md` Core не считает.
- Suggestion: Выровнять одну схему (OpenAPI Core уже описывает форму
  Core) и маппить её в адаптере; либо поменять Core DTO под Admin.
  Добавить `last_use_at = max(installations.updated_at, jobs.updated_at)`
  в том же snapshot. Покрыть контрактным тестом JSON Core ↔ Admin
  client, не только fixture.
- Status: open

### Issue 2 -- Severity: bug
- File: `/Users/nikpeskov/Projects/amocrm-pro/internal/admincommand/http.go:69`
- Description: Конфликт настроек/панели/lead-status на живом Core не
  показывает текущие значения. Activity CAS возвращает только
  `conflict: settings were updated` без тела Settings. `immediateConflict`
  превращает это в HTTP 409 `{error:{code,message}}` без `result`/
  `current`. Admin `conflictCurrent` тогда даёт пустую карту, UI пишет
  «Текущие значения: retention_days=—». Fixture как раз кладёт current
  в `result` и integration/e2e это проверяют. Приёмка «conflict shows
  current» и ADR-0028/0010 выполнены только на Demo.
- Suggestion: При CAS-конфликте читать актуальные Settings/panel/rule
  и отдавать их в 409 (или в `result` failed-операции) теми же ключами,
  что уже показывает OperationView. Тест Core должен требовать
  `initial_days`/`retention_days`/`updated_at` в теле конфликта.
- Status: open

### Issue 3 -- Severity: bug

- Description: Backfill ломается до Core. UI шлёт unix-числа
  (`unixFromDateInput`). `preflightActivity` и fixture payload ждут
