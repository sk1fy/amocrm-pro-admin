## Решение по файлам этапов Admin

`docs/plan/stage-1.md`–`stage-4.md` не удаляются:

1. они содержат критерии и фактические отчёты приёмки;
2. на них ссылаются reviews и демонстрационные runbooks;
3. удаление создаст битые ссылки и потеряет контекст контрактных решений;
4. общий объём файлов — около 68 КБ, поэтому экономия не оправдывает потерю
   трассируемости.

Чтобы их не путали с backlog, каждый файл получил явную отметку о завершении,
а `docs/plan/README.md` теперь отделяет завершённые этапы от активных
patch-планов.

## Исправленные несоответствия

- Корневой Admin README больше не утверждает, что завершён только этап 1 и что
  команды Core отсутствуют.
- «Ближайшая работа» ведёт на
  `docs/plan/connection-state-freshness.md`, а не на завершённый этап 1.
- Плановый индекс явно помечает этапы 1–4 историческими и завершёнными.
- Индекс Core audits дополнен ссылкой на датированный аудит Admin-интеграции.
- Индекс Core дополнен ссылкой на server-observability runbook, который
  находится рядом с фактическим Compose-стеком.

## Что сохранено намеренно

- `docs/reviews/` Admin и `docs/verification/` Core — датированное evidence.
- `docs/archive/` Core — исходные планы и checkpoints; индекс уже предупреждает,
  что это не текущий backlog.
- `docs/plans/2026-09-08-activity-backend-development.md` — действующая карта
  незавершённых production/pilot-задач и источник ссылок verification-наборов.
- Старые commit SHA в датированных отчётах — часть воспроизводимости и не
  заменяются текущим `HEAD`.
