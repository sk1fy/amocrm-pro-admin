# Тариф и пробный период amoCRM

## Объём

Core `24fb13f` создаёт задачу сделки на первой установке. Телефон
ускоряет задачу, вручную выставленный «Запрет работы» её останавливает.
Сведения о сроке оплаты приходят из amoSTART. Отдельного наблюдения
тарифа виджетом и даты окончания пробного периода пока нет.

Доработка охватывает передачу тарифа виджетом, проверку в Core, хранение
и ожидание тарифа в Platform, представление срока пробного периода и
причины отсутствия сделки в кабинете менеджера. Удаление, переустановка
и повторная авторизация сохраняют прежние правила создания сделки.

Platform хранит наблюдения по полям аккаунта. Строгая проверка первой
сделки ждёт тариф с датой наблюдения от начала эпизода. Кабинет использует
существующее поле `deal.reason` в очереди и карточке клиента.

При свежем переходе на технический тариф Platform запоминает статус и
имя партнёра. Карточка показывает причину последнего перехода. Ручная
правка, включая подтверждение запрета, сохраняется при повторах тарифа.
Возврат к обычному тарифу восстанавливает профиль, пока запрет
остаётся автоматическим.

## Приёмка

1. Виджет сообщает тариф независимо от формы активации.
2. Core подтверждает контекст установки и передаёт наблюдение в Platform.
3. Технический тариф останавливает первую сделку и отражается в карточке.
4. При строгой проверке первая сделка ждёт известного тарифа. Если
   ожидание длится 24 часа, кабинет показывает причину.
5. Окончание пробного периода отображается по сохранённой дате. Оплата
   подтверждается отдельным наблюдением.
6. История отражает ручную и автоматическую классификацию.
7. Локальные проверки покрывают переходы, повторы и разные порядки событий.
   Перед включением строгой проверки проверяется доставка тарифа
   поддерживаемыми версиями виджетов на целевой среде.

## Отчёт

Дата 2026-11-27. Изменения находятся в рабочих ветках Core, Admin и
виджетов.

### Реализованные экраны и операции

- В очереди установок видна причина ожидания тарифа или пропуска сделки.
- В карточке клиента видны состояние лицензии amoCRM и источник
  автоматического изменения статуса. Автоматический запрет можно
  подтвердить вручную.

### Изменения контрактов и миграции

- Core принимает наблюдение без формы активации по
  `POST /api/v1/widget/account-license` и передаёт его Platform по mTLS.
- Admin обновил контракт Platform с состоянием лицензии и источником
  классификации. Platform применяет миграции `000032`–`000034`.

### Локальная проверка

- Тесты Go с `-race`, сценарии на PostgreSQL 17, запуск Platform
  с тестовыми сертификатами, 273 теста интерфейса и проверка границ
  сборок Admin.
- Проверены сборки пяти пакетов виджетов и отдельно сценарии
  повторной отправки наблюдения.

### Выпуск

Порядок проверки виджетов и включения строгого режима приведён в
[руководстве Platform][rollout]. Для локальных тестов использованы
синтетические аккаунты и локальная заглушка корпоративной amoCRM.

[rollout]: https://github.com/sk1fy/amocrm-pro/blob/main/docs/runbooks/platform-v1.md#проверить-доставку-тарифа-amocrm
