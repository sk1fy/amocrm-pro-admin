# Редизайн экрана входа

Статус: completed. Дата: 2026-09-19.

## Объём

База: `amocrm-pro-admin` `691c45f`, ветка `feature/login-redesign`.
Core сверен на `79011d1`: маршруты, CLI и сервисные контракты не участвуют
во входе сотрудника; актуальная миграция Core — `000018`.

Одна UI-часть: светлая версия исходной композиции входа. Слева —
нейтральный постер с перспективными рамками и подписью «Всё в своём
ракурсе.», справа — белая область формы. Кнопка использует существующий
`--color-accent`, hover — `--color-link-hover`. Общий `BrandLogo` соответствует
точному SVG пользователя: `viewBox="0 0 79 79"`, исходные три столбца,
белый с прозрачностью 0.35/0.65 и третий `#5cc4bf`.

На входе и в основном боковом меню, включая мобильное меню, знак
расположен на небольшой тёмной подложке для читаемости белых столбцов.
Надпись «Ракурс» остаётся тёмной. Бирюзовый акцент не переносится на
элементы формы. Исходный бренд: [Ракурс](https://ka.rkrs.ru/).
Favicon ранее отсутствовал. Тема остальных экранов не меняется;
системный sans-serif локален для login.

Доступен только существующий вход по email и паролю. Показ/скрытие пароля,
клавиатурная навигация, состояние отправки и существующие ошибки доступны.
Семантика сессии, безопасный `next`, API и бекенд не меняются.

## Отчёт

Дата: 2026-09-19. Реализация включена в коммит с этим отчётом:
`frontend: redesign login and use the Rakurs brand logo`.
База `amocrm-pro-admin`: `691c45f`; `amocrm-pro`: `79011d1`.

### Реализованные экраны и операции

- Обновлён `/login`: светлая композиция из постера и формы, компактная
  мобильная шапка, кнопка цвета `--color-accent`, показ пароля и состояние
  отправки. Перспективные рамки — декор, не логотип.
- Общий `BrandLogo` на входе и в боковом меню приложения; геометрия
  и цвета предоставленного SVG сохранены точно, добавлена тёмная подложка.
- Сохранены email/password, серверная сессия, безопасный `next`, обработка
  неверных данных, ограничения попыток и недоступности сервиса.
- Основной агент проверил код и финальные скриншоты входа и меню.

### Изменения контрактов и миграции

- Admin API: нет; Core admin: нет.
- Миграции admin DB и Core: нет.
- Новых зависимостей и внешних ресурсов нет.

Браузерные сценарии: 401/429/500/обрыв сети, вход с клавиатуры,
показ/скрытие пароля, блокировка повторной отправки, переход на `next`.

низкие экраны прокручиваются. Motion не добавлен; transitions выключены
при `prefers-reduced-motion`.

После финальной адаптации композиции повторены lint, TypeScript, build
и пять браузерных auth-сценариев. Unit suite повторно не запускался:
логика входа и API не менялись.

Полный `make check` не запускался: часть меняет только frontend и docs,
бекендные тесты не повторялись. Build сообщает о существующем общем
chunk больше 500 kB. Начальный host-запуск Vitest/Vite не работал из-за
Linux native bindings в `node_modules`; проверки выполнены штатно в
Docker, зависимости не переустанавливались.

### Инструкция запуска и демонстрационный сценарий

- Общий запуск: [local-run.md](../runbooks/local-run.md).
- Локальный UI preview: `http://127.0.0.1:5188/login`.
- Preview-контейнер: `amocrm-admin-login-preview`, без подключения бекенда.
- Открыть страницу на desktop/mobile, пройти Tab по полям, переключить
  видимость пароля. Реальный вход проверяется в полном dev-стеке.

### Происхождение данных демонстрации

- Декор не представляет данные системы.
- Playwright использует только перехваченные fixture-ответы и вымышленные
  учётные данные. Screenshot ошибки сделан с fixture HTTP 401. Скриншоты внутреннего меню используют fixture-сессию
  viewer и пустой список сессий.
