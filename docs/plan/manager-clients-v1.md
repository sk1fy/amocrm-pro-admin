# A04. Рабочий раздел «Клиенты» в кабинете менеджеров

## Объём

Admin начинается с A03 `d0bcc0a`. Чтения и команды проверяются с Platform
P07 `e637bb6` и закреплённым контрактом P01 `a7dae9a`. В P07 работают
поиск клиентов, карточка, проекция пользователей, портрет, шаблон, ниши,
ручной срок и refresh. Вкладка истории показывает доступность источника.
Общая история событий подключается по P09 и A06.

Admin добавляет браузерные маршруты `/api/v1/managers`, используя
типизированный mTLS-клиент P01. Список, итог и курсор приходят из
Platform. Действующие grants и сессия проверяются по базе Admin.
Команды сохраняются в общем журнале перед вызовом, повтор использует тот
же ключ, версию и нормализованное тело. Синхронный исход содержит ETag
соответствующего ресурса, а фоновое обновление получает локальную ссылку
опроса. Конфликт возвращает текущую версию.

Обе очереди ведут в одну карточку аккаунта. Фильтры, сортировка, курсор
и открытая вкладка сохраняются в URL. Сводка, наши виджеты, портрет,
история и пользователи читают доступные проекции. Черновик заметки,
портрета и срока хранит исходную версию. Редактор показывает конфликт
и оставляет черновик сотруднику для явного решения.

## Приёмка

- Два сотрудника входят независимо и видят сохранённые данные.
- Новая команда со старой версией получает 409, введённое значение
  остаётся в форме.
- Список передаёт фильтры в Platform, тот же итог виден на каждой
  странице. Состояние списка восстанавливается по прямой ссылке.
- Право на чтение, изменение и ручной срок проверяется у владельца.
  Потеря ответа допускает безопасную сверку с журналом и точный повтор.
- Сбои Platform и источник без наблюдения видны в карточке. Остальной
  кабинет остаётся доступен.

## Отчёт

Результаты проверок и версии добавляются после сквозной приёмки A04.
