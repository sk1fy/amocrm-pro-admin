# Вход в кабинет менеджеров V1

## Объём

A01 из роадмапа V1. На `amocrm-pro@47d5270` Core хранит технические
установки и OAuth. Менеджерские credentials, сессии и grants принадлежат
Admin. На `amocrm-pro-admin@f3e4cb0` технический вход уже работает через
`auth.Service`. Макет менеджеров использует состояние браузера.

- [x] Добавить отдельный менеджерский HTTP-контракт, проверку hostname и Origin.
- [x] Разделить сессии по audience и хранить менеджерские grants в Admin.
- [x] Добавить явную выдачу начального доступа оператором через Admin CLI.
- [x] Собрать менеджерский экран с реальным входом и выходом.

## Приёмка

Существующая техническая сессия сохраняется после миграции. Менеджерский
маршрут проверяет host, session audience и актуальные grants. Техническая
роль сама по себе не выдаёт менеджерские права. Вход и выход требуют Origin
своего кабинета. Прямая ссылка открывает экран входа, пока сессия отсутствует.

## Отчёт

- Прямая ссылка в сборке менеджеров проверяет сессию через Admin API.
  Сотрудник с менеджерским доступом входит по email и паролю.
- `admin-cli employee bootstrap-manager` выдаёт первый доступ и сохраняет
  аудит в той же транзакции.

### Изменения контрактов и миграции

- OpenAPI описывает менеджерский вход, чтение профиля и выход.
- Миграция Admin `000007_manager_auth` добавляет audience сессий и гранты.
