# Patch-план: диагностика подключений в интерфейсе

Статус: in progress

Дата: 2026-09-14

Репозиторий: `amocrm-pro-admin`
База: карточка подключения и настройки Activity после этапов 1–4.

## Проблема

Карточка подключения и страница настроек Activity показывают полный снимок
наблюдений одним потоком. Администратор не видит итог, путает отсутствие
данных с ошибкой источника, получает сырые коды и одновременно все команды,
включая опасные. Цвета и адаптивность в этот patch не входят.

## Цель

Собрать операторский экран вокруг сценария «найти причину → сделать одно
действие → проверить результат»:

- вычисляемый итог подключения и центр проблем;
- вкладки и сводка вместо длинной ленты;
- контекстные команды и опасная зона;
- понятные сообщения вместо сырых ошибок Core;
- связанные сбои Activity как один инцидент;
- компактные таблицы доставок, задач и истории.

## Объём

Только frontend и документация. Контракт Admin API и Core не меняется:
итог подключения, расшифровки событий и группировка инцидентов считаются
из уже загруженных Observation.

Не входит: палитра команд с поиском, последовательная «полная диагностика»
новым backend-проходом, названия воронок amoCRM (в ответе только ID).

### Часть 1 — словарь и общие блоки

- Домен `connection_health` и тексты доставки/синхронизации.
- Относительное время, копирование ID, технические подробности.
- Observation: заголовок и статус разделены, источник не шумит.
- CommandAction: компактная раскладка и акцент опасных команд.

### Часть 2 — карточка подключения

- Сводка здоровья, центр проблем, вкладки в URL `section`.
- Контекстный тулбар, меню «Ещё», опасная зона.
- Инцидент Core admin auth, зависимые секции ссылаются на него.
- Таблицы доставок и задач, журнал vs фоновые задачи.
- Переключатель подключений аккаунта.

### Часть 3 — настройки Activity и список виджетов

- Общий баннер зависимости Core.
- Команды синхронизации по состоянию; блокировка при unavailable.
- Форма lead-status с грязным состоянием; пустое состояние запусков.
- Сравнительная таблица подключений аккаунта.

## Критерии приёмки

- «Проверить подключение» остаётся видимой основной кнопкой.
- «Включить» не показывается у активного подключения; пилот — одна команда.
- Удаление и сброс авторизации не стоят рядом с «Проверить».
- `core admin authentication failed` не является единственным текстом ошибки.
- Повтор доставки не растягивает disabled-кнопку на всю ширину.
- Вкладки живут в search `section`.
- `make test` frontend зелёный; e2e-строки 202 и идентификации обновлены.

## Отчёт

Дата: 2026-09-14. Коммиты: не создавались (не запрашивались).

### Реализованные экраны и операции

- Карточка подключения: сводка, вкладки, контекстные команды.
- Настройки Activity: инцидент Core, форма lead-status, sync по состоянию.
- Вкладка виджетов аккаунта: сравнительные колонки проблем.

### Изменения контрактов и миграции

- Admin API: нет.
- Core admin: нет.
- Миграции admin DB: нет.

### Результаты проверок

Проверку в браузере и полный `make check` выполняет заказчик.

### Ограничения

- Названия статусов amoCRM недоступны без нового источника.
- Фоновая полная диагностика и командная палитра не входят.
