# Независимое ревью РС-03–10

## Объём

Дата: 2026-10-04. Исходная база admin: `15466f9`, Core: `310a330`.
Ветка `codex/lead-distribution-review`; интегрирована `origin/main`
admin `dda7e84`, документационные конфликты разрешены с сохранением
диагностики распределения и актуальных уточнений webhook/интерфейса.

Прочитаны задачи и комментарии РС-09 из ClickUp, связанная приёмка
РС-03/10; фактические Core API, admin read/command и distribution owner.
Проверяются контракты, текущие права, scope установки, ошибки источника,
durable операции и восстановление без повторного PATCH.

Подтверждённые исправления:

1. GET-проверка существующего назначения доступна также для applying и
   confirming с незавершённым внешним эффектом. Core проверяет попытку,
   завершение и CAS версии; UI не подтверждает успех по одному статусу.
2. Ошибка health после 404 диагностики не превращается в утверждение
   об отсутствии capability. Timeout/5xx сохраняют unavailable.
3. Квитанция сохраняет и показывает фактический результат назначения,
   внешний эффект и безопасное основание. Успешная команда GET-проверки
   не скрывает outcome_unknown операции CRM.
4. Проверка после интеграции main: backend, frontend, PostgreSQL,
   E2E, scripts, vulncheck, документация через обязательный `make check`.
5. Исправления первого GitHub CI: внешние ссылки не зависят от соседнего
   checkout; E2E общий mutable fixture запускается одним worker,
   диагностический interceptor проверяет HTTP-статус до чтения квитанции.

Истёкшие замороженные запросы без квитанции Core исправляются владельцами
в Core и TeamOS, отдельно от реального неизвестного эффекта CRM. Admin
не удаляет guards/claims и не пишет в чужие БД. Живая amoCRM, установленный
ZIP, deploy и production cutover остаются вне этой локальной проверки.

## Приёмка

- Для unfinished attempted операции доступна безопасная GET-проверка;
  terminal/no-attempt и неизвестные состояния не предлагают команду.
- Ошибка источника сохраняет unavailable; отсутствие возможности — unknown.
- `make check` проходит на интегрированной ветке.
- Итог и ограничения записаны ниже перед подготовкой PR.

### Реализованные экраны и операции

- Исправлена недоступность GET-проверки `applying/in_flight` и
  `confirming/settled`: эти состояния остаются после обрыва worker или
  неуспешного readback, хотя Core уже поддерживает безопасную проверку.
- В истории и компактной квитанции больше не теряются состояние
  назначения, эффект и основание. Успешная команда чтения показывает
  `outcome_unknown` назначения отдельным неизвестным результатом.
- 404 диагностики с последующей ошибкой health не скрывает отказ Core
  за отсутствием capability. Проверены summary и trace.
- Подтверждены текущие проверки роли до preflight и dispatch, отказ
  viewer, scoped owner/CAS, неизменный request key после reload и
  отсутствие доступа Admin к таблицам других сервисов.

### Изменения контрактов и миграции

- Admin API: дополнительные безопасные поля `result.assignment_state`,
  `external_effect_state`, `evidence`. Новые/некорректные коды становятся
  unknown; произвольные объекты и строки не сохраняются.
- Core admin: существующие контракты и команды; новых маршрутов в этом
  patch нет. Работа owner с истёкшими запросами проверяется в Core/TeamOS.
- Новых прав и миграций admin DB нет. Старые квитанции без полей
  поддерживаются и не служат доказательством успешного назначения.

### Происхождение данных и ограничения

Docker/PostgreSQL проверяют реальные локальные компоненты. E2E используют
явный fixture адаптер, вымышленные установки/сотрудников/сделки; исходящий
PATCH amoCRM в этих сценариях не выполняется. Живые OAuth, установленный
SDK/ZIP, целевой сервер и переключение production остаются отдельной
приёмкой РС-03/08/10. Неподтверждённый реальный внешний эффект не даёт
права удалить guards/claims; отсутствие квитанции разрешают владельцы
через протокол Core/TeamOS, а не интерфейс Admin.
