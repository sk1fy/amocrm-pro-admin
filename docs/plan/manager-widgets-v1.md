# A05. Рабочий раздел «Виджеты»

## Объём

База Admin для контракта A05 — `a410e75`. Владелец товаров — Platform P08
`88ed4d8` в `amocrm-pro`. Семантику задаёт его runbook
`docs/runbooks/platform-catalog-v1.md`. Закреплённый P01 остаётся неизменным,
SHA-256 `78f2ce5efd5e842cf5fcf2f431a6a1376439bbba8561c9ca72ed1cb0a917dbf7`.

Браузерный контракт добавляет ровно пять операций `/api/v1/managers`:

| Метод и путь | Право |
| --- | --- |
| GET `/products` | `clients.read` |
| POST `/products` | `catalog.manage` |
| GET `/products/{id}` | `clients.read` |
| PATCH `/products/{id}` | `catalog.manage` |
| GET `/products/{id}/metrics` | `stats.read` |

Список передаёт `limit`, `cursor`, `q`, `line`, `availability` владельцу.
Метрики передают `from`, `to`. Чтение метрик не требует `clients.read`.
Создание возвращает `201`, обновление — `200`. ETag содержит версию
карточки `Product.version`, а не выбранную `tariff_version`.
PATCH использует `If-Match`. Повтор без изменения может сохранить версию.

POST принимает существующий технический продукт по коду и сохраняет его
UUID. Новый код создаёт продукт. Итоговый UUID нужно проверить по коду
результата или receipt, а не предполагать совпадение с ID команды.
Менеджер сохраняет полный подтверждённый набор `integration_refs`.
Справочник тарифов API не предоставляет. `tariff_version` выбирает только
подтверждённую владельцем версию или `null` для снятия выбора.

`trial_policy` сохраняет форму P01. FREE использует `free` с `null`,
отключение — `none` с `null`, TOP — `once` с 90 днями,
PRO — `once` с 7 или 14 днями. Владелец проверяет подтверждённое правило.

Команды используют UUID `Idempotency-Key`, `Origin` и `X-Requested-With`.
Неизвестный исход возвращает `202` с `ManagerOperation`, `Location` и
`Retry-After`. Опрос требует владельца intent и актуальную область цели.
Для новых команд товаров достаточно `catalog.manage`. Старые команды
сохраняют прежние проверки `clients.read` и права вида команды.

`confirmed_installations` считает подтверждённые эпизоды установки.
`to` включается как календарный день в часовом поясе владельца.
`active_accesses` показывает текущие доступы независимо от диапазона.
`activations` равен нулю при отсутствии источника G03. Интерфейс показывает
отсутствие покрытия источником и не представляет этот ноль как замер.

Эта часть фиксирует контракт, генерируемый клиент и проверки согласованности.
Обработчики, сервис BFF, политика опроса, миграции и UI выполняются после
передачи этого контракта отдельным авторам A05.

## Приёмка

- Пять операций и права браузера совпадают с P01, старые 19 операций A04
  сохраняют контракт.
- Формы Product, TrialPolicy, ProductMetrics, списков и тел команд
  совпадают с P01, включая обязательные поля, `null` и запрет лишних полей.
- Генерация включает 29 операций и воспроизводит `client.gen.go`.
- Хеш P01 не меняется.
- Реализация A05 подтверждает сохранение после перезагрузки, конфликт
  версий, точный повтор и сверку после потери ответа.
- Метрики доступны сотруднику только со `stats.read`, запись и её опрос
  доступны сотруднику только с `catalog.manage` без `clients.read`.
- UI различает отказ источника, отсутствие G03 и реальные нулевые счётчики.

## Отчёт

Контрактная часть передаётся авторам backend и UI. Сквозная приёмка A05
ещё не выполнена. Результаты добавляются после проверки реализации.
