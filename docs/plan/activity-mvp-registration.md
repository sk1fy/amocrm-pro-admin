# Регистрация MVP «Контроля активности 2.0»

## Объём

Задача [КА-01.01](https://app.clickup.com/t/1amkccgcnzw).
Сверено с Core `6ccc28e`: capability `activity`, API сессий сотрудника,
OAuth через integration `client_id`, связь установки `integration_id`
и существующие admin read API уже реализованы. Новые API и миграции
не требуются. Админка `2d097c9` передаёт grants, OAuth, pilot и установку,
но список виджетов аккаунта не показывает продукт и подменяет отсутствие
pilot значением `not_configured`.

Доработка отображает продукт по capability `activity`, связывает карточку
установки с интеграцией и её OAuth UUID, сохраняет различие между грантом,
pilot, включением установки и OAuth. Отказ источника не является пустым
списком или выключенным модулем. Расширенная диагностика, биллинг,
выпуск виджета и production deploy вне объёма этой части.

## Приёмка

- [ ] Продукт виден в каталоге интеграций и виджетах аккаунта по `activity`.
- [ ] Установка ссылается на интеграцию с её кодом и OAuth UUID.
- [ ] Грант, pilot, состояние установки и OAuth показаны отдельно.
- [ ] Unknown и unavailable не заменяются выключенным состоянием.
- [ ] Unit и e2e сценарии проверяют отображение и частичную доступность.
- [ ] `make check` и документация актуальны.

## Отчёт

Дата: 2026-10-27. Коммиты: текущая ветка `codex/activity-mvp-registration`;
Core проверяется отдельным изменением.

### Реализованные экраны и операции

- Списки виджетов аккаунта и интеграций, карточки установки и интеграции
  отображают продукт по capability `activity` и существующий грант.
- Идентификация установки ведёт к интеграции; Core ID и OAuth UUID
  `client_id` подписаны отдельно.
- Отсутствующий pilot остаётся unknown. Отказ списка подключений
  интеграции не показывается как подтверждённый пустой список.
- Новых административных операций нет.

### Изменения контрактов и миграции

- Admin API и Core admin API: существующий v1, без изменений.
- Core требует массив `grants`; неполный frontend-ответ обрабатывается
  как unknown. Unavailable блокирует отображение сохранённых фактов.
- Миграции admin DB: нет; Core: нет в этой части админки.

### Происхождение данных демонстрации

- Fixture: синтетические аккаунты и интеграции с `origin=fixture`.
- E2E отдельно подменяет публичный `client_id` вымышленным UUID,
  отличным от Core ID: проверка не допускает их перестановку.
- Real: живой OAuth/SDK и права сотрудника админкой не подтверждались.

### Ограничения и зависимости следующего этапа

- Требуются полный зелёный набор проверок, review и точная версия PR.
- Выбор реальной тестовой интеграции и живая OAuth/SDK проверка
  остаются у основного агента и пользователя.
- Deploy, пакет виджета и ручная приёмка MVP в эту часть не включены.
