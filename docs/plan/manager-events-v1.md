# A06. Лента событий и история аккаунта

## Объём

Сверено с Platform P09 `093cdb5`: владелец выдаёт события через
`internal/productplatform/manager_feed*.go`; Admin не читает таблицы
владельца. Изменяются ровно два читающих браузерных маршрута, их
контракт, генерируемый клиент и существующий реестр BFF. Закреплённая
копия P01 остаётся неизменной. UI и сквозная приёмка выполняются в
общем A06 worktree после переноса контрактных и серверных коммитов.

## Контракт

Admin начинает с A05 `d4eeb1b`. Владелец событий — Platform P09 `093cdb5`.
Формы Event и EventList заданы закреплённым P01.

| Браузерный маршрут | Операция Platform | Право |
| --- | --- | --- |
| GET `/api/v1/managers/feed` | `listFeed` | `feed.read` |
| GET `/api/v1/managers/accounts/{id}/history` | `listAccountHistory` | `clients.read` |

Список использует `limit`, `cursor`, повторяемый `kind`, `product_id`,
`from`, `to`. Глобальная лента дополнительно принимает `account_id`.
Event сохраняет исходные UUID, вид, время действия и записи, безопасное
описание и связанные объекты. Имя исполнителя опционально. Поля аккаунта
и продукта принадлежат событию, переходы определяются `related_refs`.

BFF использует существующий реестр чтений, именованный клиент, проверку
тела ответа и текущих прав до и после обращения к Platform. Новый контракт
содержит 26 браузерных операций и 31 выбранную операцию клиента Platform.

## Интерфейс

Общий Timeline получает контекст ленты либо истории аккаунта. Фильтры и
курсор используют отдельные пространства параметров `feed_*` и
`history_*`. Возврат в браузере восстанавливает открытый снимок. Явное
обновление начинает поиск с первой страницы. `invalid_cursor`, ограничение
источника, отказ прав и пустой подтверждённый результат показываются
отдельными состояниями.

Переходы используют разрешённые ссылки аккаунта, продукта и эпизода.
Эпизод открывается на вкладке виджетов аккаунта с `episode=<UUID>`.
Поиск проверяет точное совпадение `row.id` на страницах существующего
AccountWidgets. Все страницы сохраняют один `snapshot_at` и `query_hash`.
Разрешены до 100 страниц по 100 строк с общим сроком, отменой и защитой
от повторного курсора. Закрытый эпизод показывает собственные факты.
Выбор для продления явно указывает текущий продукт.

## Приёмка

- ID одного действия совпадает в глобальной ленте и истории аккаунта.
- Фильтры, пагинация и возврат работают через реальные BFF и Platform.
- Сотрудник с `feed.read` видит ленту, с `clients.read` — историю.
- Ссылки ведут к разрешённому объекту с указанным UUID.
- Удалённый эпизод за первой страницей открывается по своему UUID.
- После перезапуска читаются сохранённые действия.
- Смена прав обновляет область интерфейса и текущие запросы.
